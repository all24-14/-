# 客服工单趋势分析工具

对 50 条客服工单数据（2024-06-01 ~ 06-11）进行自动化趋势与异常分析，帮助客服主管快速定位「哪些问题变多了」「哪些异常值得关注」，把精力从翻列表转向决策。

---

## 一、分析维度设计

| 维度 | 分析内容 | 对主管决策的价值 |
|------|----------|------------------|
| **时间趋势** | 每日工单总量、各类别随时间变化（堆叠面积图） | 识别突发高峰，判断是否需临时增派人手 |
| **类型分布** | 各问题分类的数量与占比 | 定位核心问题域，指导资源与专项治理方向 |
| **严重程度** | 优先级分布、各优先级满意度 | 高优先级占比 62%，判断整体压力与风险敞口 |
| **处理效率** | 各分类平均/最长处理时长 | 找出流程瓶颈（如退款退货），优化 SLA |
| **客户体验** | 各分类满意度、满意度评分分布 | 定位体验最差的环节，优先改进 |
| **渠道分布** | 在线/电话/邮件占比、渠道 × 优先级交叉 | 评估渠道负载与人工/自助资源配置 |
| **解决状态** | 解决率、未解决工单的类别与优先级 | 识别积压风险与潜在投诉升级点 |
| **关联分析** | 分类 × 满意度 × 处理时长的交叉关系 | 发现「处理慢且满意度低」的高危组合 |

## 二、关键发现

### 总览

- 工单总量 **50 条**，平均满意度 **2.36 / 5**，平均处理时长 **19.7 小时**，解决率 **84%**。
- 支付问题（16 条，32%）与退款退货（13 条，26%）合计占 **58%**，是绝对的核心问题域。

### 五大异常信号

1. **退款退货处理时长显著异常、时效被反复投诉**
   退款退货平均处理 **45.2 小时**，是其他分类均值（10.7h）的 **4.2 倍**，最长单笔 120 小时；描述中反复出现「审核一周」「钱还没退」「还在处理中」等时效抱怨（T001/T007/T031/T042/T047）。

2. **支付类工单占比最高，「重复扣款/多扣款」反复出现**
   支付问题占 32% 居首；其中 6 条涉及重复扣款/多扣款（T012/T022/T030/T037/T046/T050），且 T046 明确提到「上个月也有过」——是反复发生的**系统性支付缺陷**（疑似回调幂等性问题），涉及资金安全，风险最高。

3. **投诉类工单满意度垫底（全部 1 分）**
   4 条投诉平均满意度 1.00，集中在客服态度差、响应慢（等待 40 分钟）、机器人无效应答，服务体验存在系统性短板。

4. **未解决工单集中为高优先级退款/支付问题**
   8 条未解决中 7 条为高优先级，平均满意度仅 1.12，多为退款/支付类资金问题，存在客户流失与投诉升级风险。

5. **物流查询满意度偏低、处理偏慢**
   物流类平均满意度 2.12（低于总体 2.36），平均处理 24.5 小时，物流信息不透明是主因。

### 建议优先级

1. **优先修复支付系统重复扣款缺陷**（资金安全，最高风险）
2. **优化退款流程时效**（设 SLA 阈值 + 自动催办）
3. **提升客服服务质量**（改善响应速度与人工兜底）
4. **物流信息透明化**（主动推送物流异常预警）

## 四、运行方式

环境要求：Python 3.8+，依赖 `pandas`、`matplotlib`。

```bash
cd ticket_analysis
python analyze.py
```

> Windows 注意：若 `python` 命令指向 Microsoft Store 的「应用执行别名」（空壳，运行无输出），
> 请改用完整路径，例如 `C:\Users\20619\anaconda3\python.exe analyze.py`，
> 或直接双击仓库根目录的 `run.bat`（自动定位 anaconda Python 并运行）。

运行后自动：
- 在控制台打印异常信号与依据；
- 在 `output/` 生成 9 张可视化图表（PNG）与 `report.md` 结构化趋势报告。
